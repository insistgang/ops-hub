## 🔍 第 2 遍审阅：技术可行性、数据流与安全性 (Technical Feasibility & Security)

1. **零 Mock 假数据铁律执行力度**：
   - 数据全部由真实采集器从本地路径与网络探测生成，落盘为 `data/status.json`、`data/career_records.json` 等结构化数据。
   - 杜绝一切硬编码假数据，通过！
2. **纯净单页直出栈可行性**：
   - 选用 HTML5 + Tailwind CSS CDN + Lucide Icons + Chart.js，直接存放在根目录 `index.html`。
   - 完全不需要 `npm run build`，GitHub Pages 启用 `main` 分支根目录即刻全局生效，通过！
3. **网络心跳与端口探测可行性**：
   - Tailscale 探测实测通过（Mac `100.86.36.75` -> Win `100.98.218.25`，延迟 ~20ms）。
   - 探针设置 2 秒超时，禁止长阻塞，通过！
4. **GitOps 推送容错性**：
   - 结合用户网络实情，设计 SSH 优先、HTTPS 自动降级双协议逻辑，确保断网或端口受限时不报错崩溃，通过！

## 🔍 第 3 遍审阅：异常边界、维护成本与长期演进 (Edge Cases & Maintenance)

1. **Win 4070S 关机或休眠时的容错**：
   - 探针超时即标记为 `🔴 离线 (上次在线: X小时前)`，不影响其他数据采集与页面正常渲染。
2. **离线/弱网场景下的自愈**：
   - Git push 遇网络失败记录本地日志，下一次早晚定时触发或手动 `ops sync` 时自动重试补推。
3. **全局 CLI 工具链人机工效**：
   - 通过 `ops` 安装脚本将可执行脚本软链到 `~/.local/bin/ops`，任意终端路径直接可用。
4. **macOS 原生守护机制**：
   - 采用 `launchd`（`com.insistgang.opshub.plist`）在每日 09:00 与 21:00 自动触发，休眠唤醒后自动补测，极其省电且可靠。
