## 1. 核心架构原则与设计铁律

1. 🚫 **零 Mock 假数据铁律**：所有呈现指标（公司、岗位、网络延迟、项目提交、打卡）全部读取本地真实工程与线上真实服务。
2. 🌐 **公网完全可见与 GitOps 自动化**：
   - 采用 macOS 原生 `launchd` 守护服务 (`com.insistgang.opshub.plist`)，每日早晚（09:00 与 21:00）自动采集并推送 GitHub。
   - 支持全局命令 `ops sync` 随时一键同步。
   - **自愈与容错机制**：Windows 离线时优雅降级（标红并记录离线时长），断网时安全重试并静默记录，决不阻断运行。
   - **双协议推送机制**：默认优先使用 SSH (`git@github.com:insistgang/ops-hub.git`)，网络或认证不通时自动回退为 HTTPS (`https://github.com/insistgang/ops-hub.git`)。
3. 🖥️ **页面架构与部署**：
   - 采用 **Tab 切换式现代工作台**（Tab Navigation Dashboard）。
   - 根目录直接放置 `index.html` + `css/` + `js/` + `data/`，GitHub Pages 选择 `main` 分支根目录，免去任何构建动作。
4. ⚙️ **系统级 CLI 人机工效**：
   - `ops` 安装脚本自动软链接到 `~/.local/bin/ops`，全局任意目录可用。

## 3. CLI 工具链规格设计 (`ops`)

* `ops status`：终端彩色打印全局看板摘要。
* `ops sync`：执行全量探测，扫描本地项目，生成 `data/status.json` 并提交推送 GitHub（SSH 优先，HTTPS 自动回退）。
* `ops career <list|add|update>`：求职记录快速维护。
* `ops check <起了|动了|写了|关了>`：快速打卡今日四勾并更新状态。
* `ops memory`：快速打印个人记忆与秩序原则。
* `ops serve`：本地启动极速静态 Web 预览。
* `ops schedule <install|status|uninstall>`：管理 macOS 原生 `launchd` 早晚自动调度。
